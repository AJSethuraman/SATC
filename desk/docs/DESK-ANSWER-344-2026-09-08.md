## What my write-up got wrong, and it was the module's central premise

`browser.py`'s header said, of using a real browser:

> *"IT ALSO HAPPENS TO BE THE ONLY THING THAT WORKS."*

citing `satc-desk-tieout → 10,596 b` against `Chrome/140 → 584,798 b`.

**Both rows were curl with a user-agent string swapped.** No browser was in that
experiment. It establishes that *sending a Chrome UA string* works and says
nothing whatever about a real browser. The desk produced that original
measurement, and caught the error in its own data being quoted back at it.

Measured with the actual browser: **12,474 bytes, refused.**

> **THE HONEST CLIENT IS REFUSED. THE MISREPRESENTING ONE IS SERVED.**

Mechanism, established with no network and no misrepresentation — a page
printing `navigator.userAgent` under the same flags:

```
Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko)
HeadlessChrome/152.0.0.0 Safari/537.36 | webdriver=false
```

**Reproduced here before anything was built on it**, on a different machine and
a different Chromium: `HeadlessChrome/141.0.0.0 | webdriver=false`, and `FLAGS`
sets no `--user-agent`. So eCFR flags the token `HeadlessChrome` exactly as it
flagged `satc-desk-tieout`. `webdriver=false`, so this is not automation
detection — it is the string.

**The desk declined to propose the fix that follows, and was right to.**
`--user-agent=Chrome/140` would very likely work and is precisely the false
statement the firm ruled out on the docket. In its words: *"That is their
decision and it is now a sharper one than when they made it: honesty here costs
access, and the write-up's 'it also happens to be the only thing that works' was
the sentence that hid the cost. The ethical argument stands on its own and does
not need the empirical one — which is just as well, because the empirical one is
inverted."*

**Everything else in the write-up held**, checked by the desk: both defects
reproduce as described, `--no-sandbox` is correctly never added on Windows, and
the redirect-to-canonical case is real — it appears on the curl row, which
redirects, while the interstitial does not.

## The fix that went in: DIFFERS now requires evidence

There is a **third refusal shape**, and the two existing guards miss it by
construction:

| shape | caught by |
|---|---|
| bounce to `unblock.federalregister.gov` | the landed-host check |
| Chromium's own error page | the body-class check |
| **"Request Access" in place — right host, 200, bare body, no `ERR_`** | **nothing** |

The desk named the general check rather than another blocklist:

> *"DOES THE FETCHED DOCUMENT EVEN MENTION THE SECTION WE ASKED FOR? Every
> citation carries its own identifier, so this needs no per-publisher
> knowledge."*

Measured against that interstitial — and note the last two rows, which are why a
check on the publisher's name would have missed it:

```
'1.263(a)-2'              in body: False
'263(a)-2'                in body: False
'Amounts paid to acquire' in body: False
'eCFR'                    in body: True
'Request Access'          in body: True
```

And the verdict it should produce is **COULD NOT, not DIFFERS**. From our own
side, "the publisher changed the text" and "the publisher refused us" are the
same observation, and only one of them is a finding about the publisher. DIFFERS
withdraws a citation, so it should require positive evidence that this **is** the
right document; absent that, the honest verdict asks a human to look rather than
telling one to retire a rule.

`proving._absent` does this. **It can only turn a DIFFERS into a COULD NOT and
never the reverse**, so the engine can only become more cautious. The cost is
real and is the right way round: a rule that genuinely moved, on a page that does
not name itself, is now reported as unchecked rather than withdrawn — and
`staleness.py` reports drift separately.

**Two mutations survived the first version of the tests, and both were the same
fault:** every fixture put the citation in the page *exactly as cited*, so the
two rules that make the check work on a real document were never exercised. A
desk cites `1.263(a)-2(d)(1)`; the page is headed `1.263(a)-2` and contains the
full path nowhere. Constructed controls now pin both.

## Still open, and it is the firm's

**Whether the tie-out may send a browser user-agent string.** The docket answer
was *"Real headless browser"* and this run does not change what that means — it
changes what it costs. As it stands the transport is honest and eCFR refuses it,
so a citation no desk holds cannot be proved against that publisher at all. The
alternatives are: accept the refusal and escalate to a person; use the developer
API the interstitial itself points at; or reconsider the user-agent. Only the
firm can pick.
