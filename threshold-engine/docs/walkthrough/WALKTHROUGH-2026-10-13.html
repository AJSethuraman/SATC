The walkthrough, run in Excel

threshold-engine on public data, 13 October 2026. Excel 16.0, through its automation interface. 433 of 433 cells as expected, in 30 of 30 steps.

What was done

The expected answers come from expected.py, from the source files and scale.py. 355 of them were written and committed before Excel was first opened (commit 6f3505d); the rest were added after a run, each listed below under What I got wrong. walk.ps1 then built the workbooks with the same command a person types, opened them in Excel, typed each step's values into Assess's inputs, let Excel recalculate, and read every cell back from Excel. Nothing was read from Python. compare.py put each reading beside its expected answer: a number must agree to within 1e-9, text exactly. After every step the typed cells were put back, and the Check column read blank again.

The card lines with the crisis and the pandemic left out (step W5) are held to a record made a week earlier, not to scale.py: LOG.md, 7 October 2026, 3.171 / 3.464 / 4.050 / 5.981, with 25 / 22 / 29 / 55 / 4 quarters kept in each score. One card line is tied out separately to the Federal Reserve's own table (docs/tie-out/cards-moderate-line-2026-10-13/).

What it looked like

What it found

  • Assess drew the wrong bands for three of the four products. For a product whose data starts after the first quarter on the calendar (mortgage 1991, home equity and other consumer 1992), the chart's top and floor were MAX and MIN over a column holding #N/A, so both were #N/A: Low and High vanished and the other bands were drawn from zero. Every count was right; only the picture was wrong. The tests charted cards only, which covers the whole calendar. Fixed with a helper column that is blank, not #N/A, and a test for each product.
  • A credit score drew from zero. For a measure not floored at zero the chart's floor now sits just under the data, and the axis, which Excel starts at zero unless told otherwise, is given a fixed round minimum at build. The strip for periods left out now stands on an invisible base so it no longer pulls the axis down.
  • The Chart tab's legend covered the cutoff lines' right-hand ends. It sits below the plot now.
  • WHAT-IT-DOES.md said the Glossary has 33 terms; it has 35. The script's expected answer came from that document, and Excel disagreed. The document was wrong and is corrected.
  • The card file in the repository is rounded to three decimals, which moves every card line by 0.0005 against the Federal Reserve's own figures and changes no score: see the tie-out.

What I got wrong

  • The script's first card reference was LOG.md of 6 October, which belongs to the scale retired that evening. The 7 October record is the one for this scale; the script stopped on the mismatch before anything was run.
  • Four readings failed on the first run because of the runner, not the workbook: a formula that returns a cell came back as a cell object, and #N/A in a hidden column reads as blank text. Both are read correctly now.
  • Not every answer was written before the first run. Committed first (6f3505d): 28 steps, 355 cells. Added after: steps W14a and W14b whole (the lower-is-worse workbook, 36 cells, then more for its chart's floor and top), and readings of the chart's floor and top in W3.1–W3.4, because the first run showed the pictures wrong while every cell read was right. The Glossary count was changed from 33 to 35 when Excel disagreed (the document it came from was wrong), and to 36 when the Status term was added. The run on the Assess redesign added the Periods left out, Status and Scenarios readings. An independent check found this paragraph missing from an earlier version of this document, which said every answer was written first.

What this does not prove

  • A person's hands. Excel did the arithmetic and drew the charts, but the typing was done through its automation interface. The window (Thresholds.pyw) was not walked here; its tests drive it, and three open a real window.
  • Every dial row. Three dial rows were read against Thresholds (W6–W8); the tests hold every row to scale.py.
  • Evidence and Backtest are written at build by the same Python the expected answers came from: W13 shows they reach Excel intact, not that they are right. The tests and the 12 Oct tie-out cover them.
  • The peer workbook is not in this walkthrough. It was run end to end and tied to KeyBank's filed Call Report on 12 October (docs/tie-out/keybank-card-90plus-2026-10-12/).
  • The bank's data. Nothing internal was run. The on-site checklist covers that, at the bank.
