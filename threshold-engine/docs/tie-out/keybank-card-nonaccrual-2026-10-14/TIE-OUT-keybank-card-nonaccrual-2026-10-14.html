Link 3 · The derivation

  1. peers/delinquency.py: for Credit card the balance field is LNCRCD and the nonaccrual field is NACRCD (FIELDS); the measure nonaccrual uses only that numerator (MEASURES).
  2. bank_delinquency(…, cert "17534", "Credit card", "nonaccrual", …) takes the 2026Q2 row as filed: numerator 6,401, balance 926,589. KeyBank is exempt from the 1,000,000 minimum book. The jump and acquisition rules only blank a four-quarter average, never a quarter-end rate.
  3. Rate = 100 * num / bal = 100 × 6,401 ÷ 926,589 = 0.6908132947833397. peers build writes it to credit-card_keybank_delinquency-nonaccrual_quarter-end.csv, row 2026-06-30,0.6908132947833397 (a copy is beside this document). Its header says "quarter-end rate: 100 x NACRCD / LNCRCD, both from the same filing, %. Amounts are $ thousands at quarter-end, as filed".
  4. book reads that CSV and workbook.py writes the last point twice, as a value: Data!N83 (the column) and Thresholds!J17 (th.cell(r, 10, lp.value)). Neither is a formula.
  5. Summary!G11 is INDEX(Thresholds!$J$5:$J$99, MATCH("Credit card - Nonaccrual - KeyBank", Thresholds!$A$5:$A$99, 0)). Decide's headline is TEXT(INDEX(Thresholds!$J$5:$J$99,$AA$3),"0.00"), where AA3 is the Thresholds row of the one series the slicers leave showing. So both show J17, and 0.69 is J17 rounded to two places for display.

5 · What it found

  • The figure is right, to the last digit Excel holds. 0.6908132947833397 on Summary, Decide, Thresholds and Data is exactly 100 × 6,401 ÷ 926,589, KeyBank's filed RC-N 5.a column C over RC-C 6.a column A.
  • The two FDIC fields are the two filed lines, for every bank. The FDIC's dictionary gives NACRCD and LNCRCD a title and a sentence, no line number. Against the FFIEC's bulk file for 30 June 2026, NACRCD equals B577 and LNCRCD equals B538 for all 4,295 banks in both, to the thousand. Neither is a sum. So the mapping delinquency.py relies on is shown, not assumed, for this quarter.
  • Thresholds!J (Latest value) is a typed value, not a link to the Data tab. Summary and Decide follow Thresholds!J by formula, but nothing in Excel ties J17 to Data!N83. They agree because Python writes both from the same list. If somebody pasted a corrected quarter into Data, the lines would move and Latest, the rating, Summary and the Decide headline would not. That may be intended; it is the one hop in the chain that is not live.
  • The Thresholds tab's Series column is clipped in Excel. Column A is 15 wide and B is never empty, so row 17 shows Credit card - Non (the picture above). The three sources of one measure read the same there, so a reader cannot tell the rows apart on that tab. On Summary, H7 and H8 show Not in this workbool, the last letter cut off.
  • The cross-bank comparison beside this figure is mostly policy, and the warning is on another tab. Decide says KeyBank is 0.68 points higher than Peer group (15 banks) and Summary shows +0.68. At 30 June 2026, 10 of the 16 roster banks filed zero card nonaccrual (counted here from the FDIC call for every filer). They report late card loans as 90+ still accruing instead. The workbook says so only on the Sources tab. KeyBank's 5 High is against its own history and is not affected.
  • The FDIC's dictionary labels both fields "( YTD, $ )". Both are quarter-end balances, not year-to-date, and both are in thousands, as the 4,295-bank match against the filed $000 lines shows.

6 · What I got wrong

  • I expected the FDIC's definitions file to name the Call Report line for each field. It does not, so the field-to-line answer had to come from the numbers: the every-bank check above.
  • The first Excel read printed 0.69081329478333975 and the CSV says 0.6908132947833397. Different text, the same number: .NET prints 17 digits, Python the shortest that round-trips. I checked by parsing both before writing "diff 0".
  • read_workbook.ps1 first passed Excel a relative output folder. Excel resolved it against its own folder and the picture export failed (STG_E_PATHNOTFOUND). It now resolves the path first. Its first successful run also recorded PowerShell's stray output in the list of pictures; fixed.
  • The comparability tie-out's capture script needs pdftoppm and pdfplumber, which are not on this machine. capture.py here does the same cuts and rings with PyMuPDF.

7 · What this does not prove

  • One figure, one bank, one quarter. The other 94 series and the other 55 quarters of this one (2012Q3 to 2026Q1) come through the same code and are assumed right because of that. That is an inference, not something this check ran.
  • Not the firm's own build. This workbook was built with peers switched off, from series CSVs a peers build wrote earlier the same evening from a cache pulled at 10:58 that morning. book books\consumer-public.json, which runs the peers build itself, was not run. Step 2 above reads that build the same way.
  • Not the rating. 5 High depends on the lines (median, typical move, the settings on Decide). Those are judgements, not filed figures, and nothing here ties them.
  • Not the peer group's 0.01 or the +0.68 difference. Only KeyBank's own figure was tied.
  • Field-to-line for one quarter only. The every-bank check is for 30 June 2026. The FDIC's definitions say both fields were wider before 2001. This series starts in 2012Q3, but other quarters were not checked. 18 FDIC rows have no match in the FFIEC bulk file (17 with both fields blank, one with both 0), and one FFIEC filer (State Bank Northwest, cert 2945) has no FDIC row. Not looked into.
  • Amendments. The filing says Last updated 7/30/2026, and the FDIC's data is index risview_20260819185831 (19 Aug 2026). An amendment after that would be in today's filing and not in the FDIC's data. Today's XBRL agrees with the API on both lines, so no amendment has touched them.
