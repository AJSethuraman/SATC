Link 3 · The derivation

  1. Each quarter in the file is the mean of four quarterly Fed rates, ending in that quarter, saved to three decimals.
  2. Quarters kept: every quarter except 2007Q4–2012Q4 and 2021Q3–2023Q1. 163 quarters, 135 kept.
  3. Median kept: the middle of the 135 kept values (Data!F, =MEDIAN).
  4. Typical yearly move: every four-quarter change whose both ends are kept (123 of them), then 1.4826 × the median absolute deviation of those changes.
  5. 3 Moderate from = median kept − half-width × typical yearly move = median − 0.5 × move.

5 · What it found

  • The repository's public card file is rounded to three decimals, and that moves every card line by 0.0005. A four-quarter mean of rates published to two decimals is exact at four. In 80 of 163 quarters it ends in 5, and the file keeps three, rounded by Python's floating-point rounding: 43 went up and 37 down (2026Q2: 3.9775 saved as 3.978; 2020Q2: 3.7575 saved as 3.757). 2020Q2 is the median kept under the rehearsal settings, so the median, and every line built on it, is 0.0005 lower than the Fed's figures give. No kept quarter and not the latest changes score.
  • It touches nothing the bank will run. On site the workbook reads the bank's own files. The rounding is in a test file made before this check, and the tests compare the workbook with the reference on that same file, so they could not see it. Only the Board's table could. The file is left as it is, so its fingerprint and every test built on it stand; this document and LOG.md record its precision.

6 · What I got wrong

  • A first quick comparison flagged only 13 of the 80 rounded quarters: it compared in binary floating point, where most exact halves land a hair inside 0.0005. derive.py compares in exact decimals and finds all 80.
  • The walkthrough's script first took its card reference from LOG.md of 6 Oct (3.757 / 4.469 / 5.180 / 5.892). Those figures belong to the scale retired that evening. The 7 Oct figures for this scale are the ones it now holds the workbook to.

7 · What this does not prove

  • One product. Mortgage (CORSFRMACBS) is built the same way and likely carries the same rounding; it was not tied here. Home equity and other consumer come from FDIC sums, a different road, and were not tied.
  • Not the bank's numbers. The scale on KeyBank's internal data is run on site; nothing here says those files are right.
  • Revisions. The Board revises history. The file and the table agree today within rounding in all 163 quarters, so no revision has moved a value since the file was made; a later release may.
  • One reading of the full table. All 166 quarters were parsed from the page; only the four latest were also read by eye. FRED, the second publisher, could not be reached.
