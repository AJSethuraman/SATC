# Triage

Sort incoming issues/PRs into a clear next action, and produce the
**`ready-for-agent`** brief that lets an agent start immediately.

## Category (pick one)
- `bug` — something broken
- `enhancement` — new feature or improvement

## State (pick one)
- `needs-triage` — awaiting evaluation
- `needs-info` — waiting on reporter details
- `ready-for-agent` — fully specified; an agent brief is attached
- `ready-for-human` — needs human implementation
- `wontfix` — will not proceed

## Process

1. **Gather context** — read the issue/PR, comments, labels, and (for a PR) the
   diff. Check for prior triage notes, redundancy already in the codebase, and
   anything previously rejected.
2. **Recommend** a category + state with reasoning.
3. **Verify the claim** — reproduce the bug, or confirm the PR diff matches its
   description. Don't take it on faith.
4. **Grill if under-specified** — sharpen requirements with questions (use
   `grill-me`), and fold the answers into the issue.
5. **Apply the outcome:**
   - `ready-for-agent` → post an agent brief (what to build, acceptance
     criteria, the testing seam, blockers). This is what `to-issues`/build
     consume.
   - `ready-for-human` → explain why a human is needed.
   - `needs-info` → post established facts + the specific open questions.
   - `wontfix` → close with the reason.

## Rules

- Prefix every triage comment with: *"This was generated by AI during triage."*
- Tag PRs `[PR]` and issues `[issue]` in discovery lists.
- Be frugal with comments — post only what's needed to move the item forward.
