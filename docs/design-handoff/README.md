# Pricing page — design handoff

Three static snapshots of the real page, captured 26 August 2026. Real copy,
real prices, no JavaScript. Open them in a browser or hand them to a design
tool; each stands alone apart from the Google Fonts link.

| File | What it is |
|---|---|
| `pricing-individuals.html` | The price page as it opens — the four 1040 packages |
| `pricing-businesses.html` | The same page with the Businesses tab showing |
| `home.html` | The existing home page, for the shell, nav, type scale and palette the pricing page has to match |

**The tab switch is inert in these files.** The live page renders both panels
from `website/pricing-config.js`; these are flattened so the content is in the
markup where a design tool can see it.

---

## What the layout is free to change

Everything visual. Spacing, type scale, card shape, colour weighting, the order
of the sections below the prices, how the switch looks, how the extras table
reads on a phone. None of that is settled and the current version is a first
pass — the four cards, the grouped rows and the tab strip were built to be
correct, not to be finished.

## What must survive any redesign

These are firm decisions, not preferences. Each one is enforced by
`website/pricing.spec.py` (58 checks), which runs in CI — so a redesign that
breaks one will fail the build rather than reach the site.

**1 · A package price and an entity price must not look like the same kind of
number.** The four 1040 packages are *gated* on what is on the return, so the
price a visitor reads is the price they get. The three entity bases are
*floors*. Today the difference is carried by a gold top rule instead of navy,
and by `from` set beside the amount. Change how that reads if you can do it
better — but a bare `$950` styled like a flat `$500` is the specific failure to
avoid, because it gets read as a total.

**2 · The word `from` stays on entity prices.** Wherever it ends up.

**3 · An entity card's bullets are what costs EXTRA. A package card's bullets
are what you GET.** They are opposite meanings in identical-looking lists,
which is why the entity list is labelled *"On top of that:"*. If the cards get
redesigned, that distinction has to survive in some form.

**4 · No price appears without what it covers.** Four bare numbers reproduce
exactly the problem the firm set out to fix.

**5 · The dark band under the packages is load-bearing copy**, not a decorative
divider: *"Every package covers your federal return, plus your first state and
first local return."* Without it every per-item price below reads as double
charging. It can move or restyle; it cannot go.

**6 · No explanatory preamble above the prices.** One headline, one line of
lede, then the numbers. *"Just let the prices speak."* The switch is a control
and belongs there; a paragraph does not.

**7 · Package names are data, not markup.** They render from config because
one of the four has already been renamed once, and more may change. Do not bake
`Simple Filer`, `Essentials`, `Standard` or `Self-Employed` into the HTML.

**8 · Nothing is added to this page.** The prices shown are the only ones
cleared for publication. Two real charges are deliberately absent and must stay
absent; the schedule records why.

## The copy rule

Client-facing copy is a different register from anything internal — see the
"Client-facing copy is a different register" section of the repo's `CLAUDE.md`.
Short version: no term a first-time reader would have to look up, no
contract-desk vocabulary, and no sentence past ~28 words. Both of the last two
are machine-checked.

If copy needs to change to serve a layout, say so rather than rewriting it —
several sentences here are the firm's exact words and were arrived at over
several rounds.

## Where the real files live

```
website/pricing.html            markup + styles + the render script
website/pricing-config.js       GENERATED — every figure comes from the schedule
website/build-pricing-config.py the generator; page copy that is not a figure lives here
website/pricing.spec.py         the 58 checks
```

`pricing-config.js` is generated and regenerated by the checker, so prices
cannot be edited on the page. Changing a number means changing
`client-documents/registry/fee-schedule.yaml`.
