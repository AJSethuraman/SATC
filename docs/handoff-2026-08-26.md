## What was built

**The fee schedule is finished.** `pricing.open_amounts()` returns `[]` for the
first time, and a test now treats a returning `[CONFIRM:` as a regression. Four
packages — Simple Filer $100, Essentials $200, Standard $325, Business $500 —

engagement — nothing retyped, and billing over the estimate refuses without a

`cli.py ladder` is the sanity check above.

live in `fee-schedule.yaml` under `phrases:`, with a test that fails by name if
one loses a slot or gains one nobody fills.

## The bugs, because they share a shape

Every one was **the software saying something was fine when it was not.** That
is the class worth hunting in this codebase, and it is why "debug thoroughly"
was the right instruction rather than "add features".

1. **The onboarding letter asked the client for nothing.** Every letter this
   project ever rendered said *"Below is everything we need to start your work"*
   and then listed nothing, because nothing built `RequestList` and an `[[EACH]]`
   over an empty list leaves no token for the strict check to catch. It was live
   on a document that goes in every signing pack.
2. **A refused signing pack left a stale one looking current.** The command
   printed "No pack written" and left a complete pack for a *different*
   engagement sitting in the folder.
3. **`doctor` cried wolf.** It reported `hard_no` as blocking every real render
   while real packs were rendering. A readiness tool that overstates what is
   broken teaches whoever reads it to stop believing the parts that are true.
4. **A duplicate YAML key.** A restructure left `amount: 45` twice in the rental
   block. YAML takes the last silently: the fee writer changed the first, the
   loader read the second, nothing failed, and the price would not have moved.
5. **The either/or allowance scored branches on raw counts**, so a landlord with
   a side gig won an allowance they could not spend and paid for the rental.
6. **The fee writer could not rewrite a price** whose digits appeared anywhere
   else in a two-thirds-comment file.

Each has a test. Several were found by testing a *refusal* path rather than a
success path, which is the lesson worth carrying: this pipeline's failures are
quiet, so the interesting tests are the ones that assert something does not
happen.

`has_dependents`, then `other_income_documents`. The comment in `_ladder_shapes`
