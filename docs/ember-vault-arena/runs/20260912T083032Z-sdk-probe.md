## The line FORGE.md asked for

**`model_usage` had exactly one key: `claude-opus-5`.** One model, billed once.
`canonicalModel: claude-opus-5`, `provider: firstParty`, `costBasis: list`.

## What it answers

**The alias resolves to `claude-opus-5`.** No second model is billed, so the
5.5× gap is not a hidden helper model.

**The SDK prices list rates on the counts it reports — exactly.** For this
call, at the repo's own table ($5/M in, $25/M out):

```
457 × $5/1M  = $0.002285
  4 × $25/1M = $0.000100
               ---------
               $0.002385  ← equals total_cost_usd to the cent
```

So `total_cost_usd` is not an approximation and not a different rate card. It
is list price on whatever tokens the SDK believes it sent.

## Therefore the arena's recorded counts are not the counts it was billed on

The same arithmetic applied to a real arena call (dask, from
`runs/20260912T082930Z-ledger-reprint.md`: in 2, cached 2,060, wrote 0,
out 341, cost $0.0525):

```
   2 × $5/1M       = $0.000010
2,060 × $0.50/1M   = $0.001030   (cache read, a tenth of input)
  341 × $25/1M     = $0.008525

                     $0.009565   against $0.0525 recorded — 5.5× apart
```

The shortfall is **$0.042935**, which at $5/M is **about 8,600 uncached input
tokens** per call that the ledger does not record. Cache reads cannot account
for it: it would take 85,870 of them, and the ledger says 2,060.

## Where the divergence most likely lives

Named as a candidate, not a diagnosis — this session does not edit `code/arena`:

- `usage` carries an **`iterations` array**. On this one-turn probe it holds a
  single entry equal to the top-level figures. If the CLI runs more than one
  iteration for a schema-constrained arena call, the top-level `input_tokens`
  may describe only part of the work while `total_cost_usd` covers all of it.
  The probe cannot show this, because a one-word prompt produced one iteration.
- `model_usage[model]` carries its own `inputTokens` / `cacheReadInputTokens`
  and its own `costUSD`. On this probe they agree with `usage`; in the arena
  they cannot both be right, since `costUSD` is list price on *its* counts.
  Reading the counts from `model_usage` rather than `usage`, and asserting
  `sum(model_usage costs) == total_cost_usd`, would make the ledger
  self-checking.

The cheapest next measurement, if the cloud wants it: have the probe send a
real compiled arena prompt with the action schema attached, and print both
`usage` and `model_usage`. That distinguishes "the CLI sends more than we
compile" from "the top-level usage under-reports a multi-iteration call". It is
one call and this session can run it on request.
