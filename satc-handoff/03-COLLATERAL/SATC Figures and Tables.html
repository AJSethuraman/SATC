SAT-C LLP · figures & tables

The conventions that make a document read as accountants' work.

Type and colour set the tone; the numerals establish competence. Get negatives, alignment, and totals right and a statement reads as professional before anyone checks the arithmetic. Get them wrong and good design can't rescue it.

02

Conventions

US practice throughout — dollars, US date order, GAAP-style parentheses.

NumeralsIBM Plex Mono, tabular figures, always. Never a proportional face in a numeric column. font-variant-numeric: tabular-nums even on mono, so a browser can't substitute.
AlignmentNumeric columns right-aligned; the decimal point aligns as a consequence. Description columns left. Never centre a number.
DecimalsMoney: always two, including round amounts — $300.00, never $300. Hours: one — 14.0. Percentages: one or two, consistent within a document.
NegativesParentheses, never a minus sign: (1,500.00). This is the accounting convention and it survives photocopying, which a red minus does not. Never use colour as the only signal.
Paren alignmentGive positive figures padding-right: 1ch so they align with the closing paren of negatives. Without it the column visibly steps.
Currency · invoicesOn an invoice or statement of account, put $ on every populated row of a money column. Long tables may instead put Amount ($) in the header and drop it from cells entirely — pick one per document. No space after the symbol.
Currency · statementsOn a financial statement — balance sheet, income statement, any GAAP-style presentation — the convention is stricter: $ on the first row of each column and on totals only. Use money(n, {symbol: false}) for the intermediate rows.
Currency · creditsFigures already in parentheses omit the symbol in both conventions — (1,500.00), never ($1,500.00) inside a column that already carries it. The parentheses are doing the work.
Nil vs. zeroThese mean different things and accountants read the difference. Em dash — = nothing to report. 0.00 = a computed result that came to zero. An empty cell = not applicable to this row.
ThousandsComma separators above 999 — $1,137.50. No separator in years, invoice numbers, or account references.
SubtotalsSingle rule above, in navy, 0.5pt. No fill band — toner floods it and it costs nothing in legibility.
TotalsSingle rule above, double rule below. The double rule is the traditional signal that a column is closed, and it's the cheapest credibility on the page.
Column orderDescription → quantity → rate → amount. Amount is always the rightmost column, so the eye finds the number it's looking for in one place.
DatesProse and letterhead: August 13, 2026. Tabular: 08/13/2026. Filenames and data: ISO 2026-08-13, so they sort. Ranges take an en dash — Jul 1 – Jul 31, 2026.
PeriodsState the period on every statement, in full: "For the period ended July 31, 2026." Never just a month name.
RoundingIf figures are rounded, say so in a footnote. Never let a column's displayed rows fail to sum to the displayed total — adjust the largest line or footnote the difference. An accountant will add it up.
Print hygieneLong tables get a real <thead> so it repeats on every page. Rows get break-inside: avoid. Row separation by hairline rules, not zebra fill.
The one that matters most: negatives in parentheses. It's the single fastest signal to anyone who works with financial statements that the document was produced by someone who does this professionally — and a red minus sign is the fastest signal of the opposite.
03

Implementation

Lift these directly. The CSS is framework-free and works in the web app and in the print templates alike.

CSS · the ledger table
/* figures */
.num {
  font-family: var(--mono);
  font-variant-numeric: tabular-nums;
  text-align: right;
  white-space: nowrap;
  color: var(--navy);
}
/* reserve the closing paren so columns align */
.num.pos { padding-right: 1ch; }
.num.nil { color: var(--ink-2); }

/* subtotal: rule above */
tr.sub td {
  border-top: 1px solid var(--navy);
  border-bottom: 0;
  font-weight: 600;
}
/* total: rule above, double below */
tr.tot td {
  border-top: 1px solid var(--navy);
  border-bottom: 3px double var(--navy);
  font-weight: 600;
}

/* print */
@media print {
  thead { display: table-header-group; }
  tr { break-inside: avoid; }
}
Formatting · one helper, used everywhere
// The only place money becomes a string.
// Negative => parentheses, never a minus.
function money(n, { symbol = true } = {}) {
  if (n === null || n === undefined) return "—";
  const abs = Math.abs(n).toLocaleString("en-US", {
    minimumFractionDigits: 2,
    maximumFractionDigits: 2
  });
  const s = (symbol ? "$" : "") + abs;
  return n < 0 ? `(${s})` : s;
}

money(2450)      // "$2,450.00"  — invoice row
money(-1500)     // "($1,500.00)"
money(-1500,{symbol:false}) // "(1,500.00)"  — credit
money(2450,{symbol:false})  // "2,450.00"   — fin. stmt row
money(null)      // "—"

// Default symbol:true suits invoices and statements
// of account. For GAAP-style financial statements pass
// symbol:false on every row except the first and totals.
