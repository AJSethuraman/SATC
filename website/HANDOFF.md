# Owning the SATC website

For the session that takes this over. It assumes you know nothing about this
repository and it does not restate rules that live elsewhere — **it tells you
where each rule actually lives, what enforces it, and why it exists.**

Restating would create a second source of truth that drifts, which is the
failure most of this document is about.

Written 7 September 2026 from a 26-agent sweep of the repository, its git
history, and the firm's own recorded words. Every claim was checked against the
repo by a second agent before it was written down; 64 claims did not survive
that check and are not here. One of them was an invented `$350` price.

## 1 · The blast radius

**A merge to `main` publishes to satcllp.com.** Two paths fire:

- `.github/workflows/pages.yml` — GitHub Pages, filtered to `website/**`
- **Cloudflare Pages** — production branch `main`, **no path filter**. Its build
  copies `website/` and deletes `*.md` and `*.py` from the output.

There is no staging and no review gate. The firm's standing instruction, from
`canon/CONVICTIONS.md` C2:

> Never push to main: it publishes to the live domain satcllp.com through
> Cloudflare Pages.

**Branch pushes get a Cloudflare preview**, which is how the firm reads a change
before it is live: `https://<branch-name>.satc-bdx.pages.dev`. Use it. It is the
only way to show them a page without publishing it.

A related instruction, from the firm on 30 August (`canon/corpus/decisions-in-their-words.md`):

> You shouldn't ever touch the website itself. That is another agents job.
> Merge whatever else

That was addressed to the practice-ops side, not to you — **you are the other
agent.** It is why `docs/website-agent-handoff.md` exists: a diagnosis someone
else wrote because they were not allowed to fix `website/` themselves.

## 2 · Generated files — never hand-edit

| File | Generated by | Rebuild |
|---|---|---|
| `website/pricing-config.js` | `build-pricing-config.py` from `client-documents/registry/fee-schedule.yaml` | `cd website && python3 build-pricing-config.py` |
| `website/guides/*.html`, `guides/guide.css` | `build-guides.py` from `docs/guides/*.md` | `cd website && python3 build-guides.py` |

Both have a regenerate-and-diff check, so a hand-edit fails CI rather than
silently reverting on the next build. The reason, from `build-pricing-config.py`:

> The pricing brief's rule zero is *read the schedule, do not retype it*. A
> static site cannot call Python at request time, so it does the next best
> thing: every figure, label, note and publish decision on the page is written
> here by machine … Retyping a price is therefore not a thing anyone can do by
> accident.

**One exception worth knowing:** the short `who` line under each price and the
card bullets are *not* generated from the schedule. They live in `SITE_COPY`
inside the generator, are the firm's wording, and carry no figures.

**`website/site-config.js` is hands-off** — contact email, Formspree ID, booking
link. The firm: *"SATC_CONFIG now lives in website/site-config.js, not
index.html. Still hands-off."*

## 3 · The checks, and the incident behind each

Run all of these before you push. None takes more than a few seconds.

```
cd website && python3 pricing.spec.py        # 66 checks — page vs fee schedule
cd website && python3 copy.spec.py           # 36 checks — house style, all pages
cd website && python3 build-guides.py --check # generated pages match drafts
python3 docs/guides/tenets.spec.py           # the guides' own tenets
python3 docs/guides/verify_sources.py        # every tax claim vs its cited page
```

**`pricing.spec.py`** regenerates `pricing-config.js` and fails if the committed
copy differs, so it also catches a schedule change nobody propagated.

It was **sidelined on 30 August** at the firm's instruction —

> This is driving me crazy, sideline this test until further notice. Keep it as
> recurring reminder on the interview.

— because it was red on every branch, including `main`. The cause was one thing:
the schedule dropped `notice_response` and `website/` still advertised it in two
places. `docs/website-agent-handoff.md` wrote up the two edits.

It is enforcing again as of 7 September. **Read that history before you ever
turn a check off**, and note how the revert went wrong: on 3 September the
`|| true` came off the *step* and `continue-on-error: true` was left on the
*job*, so it reported as enforcing while still unable to fail — and was
described that way to the firm in writing. Check the job key, not just the step.

**`verify_sources.py` is not in CI and always exits 0.** It is a tool you run,
not a gate. See §6.

## 4 · How the firm writes, and what enforces it

`CLAUDE.md` carries six numbered rules. **Two are code, four are judgment**, and
the ones that became code have never been broken again — which is the argument
for mechanising more of them.

`website/copy.spec.py` bans, mechanically, across all six published pages:

- **`PROMISES`** (17 entries) — `business day`, `by one person`, `personally`,
  `guaranteed`, `at no charge`, `your dedicated`, `within 24 hours`, …
- **`SELF_CLAIMS`** (24) — `no surprises`, `we're upfront`, `peace of mind`,
  `trusted advisor`, `committed to`, …
- **`CONTRACT_WORDS`** — `governs`, `engagement letter`, `pursuant`,
  `at our discretion`, `shall be`, …
- **`MAX_WORDS = 28`** per sentence

Each list is a firm instruction turned into code. In their words:

> do not promise the one business day thing

> do not say things like 'by one person' in general, never promise it is by
> someone in particular

> literally do not specify stuff like we fix our own errors for free. we don't
> need to say that.

The register rule itself:

> public facing and internal are two different things … things should sound way
> more simple to our clients than it does to us.

And the failure that produced the whole section — the price page shipped
*"the engagement letter governs the work"*, and the firm's reaction:

> i would never expect a client to understand what an engagement letter is
> inherently. 'governs the work' come on.

**Passing the checks is not sufficient.** A sentence that cleared all six rules
was killed with:

> literally AI dribble, why can't you get that?

and the same complaint recurred on 7 September about a different page. If a
sentence exists to satisfy a requirement rather than to tell a reader something,
it will read as filler no matter what the linter says.

## 4a · You do not make pricing changes. Period.

The firm's standing instruction, 7 September 2026:

> You do not making pricing changes, period, you are a downstream receiver of
> pricing. if you have suggestions, you put them that way in a format where i
> can give them to the proper agent

**You are downstream of `client-documents/registry/fee-schedule.yaml`.** You
never edit it, and you never edit a price into `pricing-config.js` — which is
generated from it anyway, so the attempt would be reverted by the next build.

What you *do* own: regenerating the config when the schedule changes, and the
short non-numeric copy in `SITE_COPY`.

**A suggestion goes in a handoff block, not a commit.** Hand this to the firm to
pass to the pricing agent:

```
PRICING SUGGESTION — from the website session, <date>

What I saw on the page:
What looks wrong or unclear to a visitor:
Where it comes from:   fee-schedule.yaml <key path>
Suggested change:      (describe the outcome, not the yaml edit)
Why:                   (what a client misreads today)
Not changed by me:     confirmed — website is downstream
```

This is not a formality. The schedule is the source of truth for money, its
lines are load-bearing in `client-documents` tests, and a price edited on the
page is a price that disagrees with what the firm will actually invoice.

The constraints are **scattered across projects**, and a website session would
not think to look in `client-documents/`. This is the index:

## 6 · The guides, and why the checker is built the way it is

Three client guides live as Markdown in `docs/guides/` and are **generated** into
`website/guides/`. The firm chose this shape:

> /guides/ with one page each, and a link from the price page

Every factual claim in them is listed in `docs/guides/SOURCES.md` and
`SOURCES-entity-choice.md` with the page it came from, and
`verify_sources.py` fetches each page and checks it carries the wording
attributed to it.

**Read that file's docstring before trusting any number it prints.** The verdicts:

- `MATCH` — the page carries the quoted wording. The only verdict meaning tested.
- `UNTESTED` — the note *paraphrases* rather than quotes. **Not a pass.**
- `PARTIAL`, `PRACTICE` (the firm's own judgment, not a claim about a page),
  `NO SOURCE`, `NO MATCH`

Conventions in the SOURCES files: **double quotes mean the cited page carries
those words.** Anyone else's wording — including the firm's — goes in *italics*,
so the checker never mistakes it for evidence. A correction is recorded **in the
row, in capitals**, not quietly fixed.

**Why it is this strict.** The first version of the checker could not fail: for
most rows its only probes were a year and a form number that appear on any
relevant IRS page. It reported 37 of 89 claims verified. The firm caught one it
had passed — crypto basis reporting, contradicted by the page cited for it — and
said:

> this makes me deeply distrust your answers

The honest count at that moment was **6**. Seven citations turned out not to
carry their claim, including a `$600` 1099-NEC threshold that is **$2,000** for
tax years after 2025 (P.L. 119-21) and a RITA PDF from the **2010** tax year.

Run it for the current count. Do not cite a remembered one.

## 7 · Traps

**The decision record and the schedule can disagree, and the schedule ships.**

`docs/pricing-open-threads.md` T-03 says *"Settled 25 Aug 2026 — all six gates
added"*, listing balance sheet **$350**, payroll **$150**, inventory **$125**,
assets **$95**, first return **$250**, Form 7203 **$75**.

The fee schedule's complete set of amounts is:
`0, 15, 35, 40, 45, 50, 65, 75, 100, 175, 200, 325, 500, 800, 950`.

Four of those six are not there, and `git log -S"125"` on that file returns
nothing. The schedule now works as *starting price + `starting_note` + hourly
past the assumptions*, which is a different model from fixed adders — so the
gates were most likely superseded and the thread never re-marked.

**Do not reconcile them yourself.** Adding four prices to a public page on the
strength of a stale thread is exactly the failure this repository keeps having.
It is listed in §8 as a question for the firm.

**Hourly has four triggers, not five** — `brokerage_keying`, `foreign_company`,
`officer_compensation`, `cleanup`. Several documents say otherwise.

**Past the assumptions the fixed price stops applying; hourly is not a surcharge
added to it.** That paragraph was corrected in the schedule header on 26 August
because it previously said the opposite.

**A merge conflict switches your CI off, silently.** `test.yml` runs on
`push` to **`main` only** — on any other branch the `pull_request` event is the
only thing that triggers it. GitHub cannot build a merge ref for a conflicted
PR, so while `mergeable_state` is `dirty` it schedules **no run at all**. No
failure, no warning: the checks list is simply empty, which looks identical to
a healthy PR if you do not count it.

This branch went eleven days and three pushes with no `Tests` run and it was
not noticed, because Cloudflare deploys on every push and its
`check_suite.completed` event arrives looking like CI reporting in.

**`check_suite.completed` is not "the tests passed."** Confirm a run exists for
your head SHA:

```
gh run list --branch <your-branch> --workflow test.yml --limit 3
```

or read the PR's check runs and count them. Nine was the full set on 7 Sep 2026;
Cloudflare ran. `main` moves fast enough here that a week-old branch is usually
conflicted, so check this every time you come back to one.

**A `[CONFIRM: ...]` marker does not stop a guide page shipping** — it did not,
until 7 September. `render_body()` strips HTML comments first and the guard
inspected the stripped text, so five open questions were deleted at build time
while the pages shipped as though answered. The gate now reads the drafts:

```
python3 website/build-guides.py --publish-ready   # exits 1 while any remain
```

Run it before merging anything under `website/guides/`.
